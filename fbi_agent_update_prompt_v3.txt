## Overview

**Daemo Engine** is a self-hosted AI agent backend written in Rust that orchestrates communication between SDK-based services and Large Language Model (LLM) providers. It enables developers to build sophisticated AI agents with tool-calling capabilities, persistent conversation memory, and multi-provider LLM support.

### Key Features

- **Multi-LLM Support**: Claude, OpenAI, Gemini, Fireworks, SambaNova, Cerebras
- **Two-Phase AI Execution**: Intelligent planning followed by execution
- **gRPC & REST APIs**: Flexible integration options
- **Function/Tool Calling**: Execute custom functions via connected SDKs
- **Conversation Memory**: Persistent thread management with MongoDB or local storage
- **Code Execution**: TypeScript/JavaScript execution via Deno runtime
- **Vector Search**: Semantic function and memory discovery via Voyage AI embeddings
- **Credit-Based Billing**: Built-in usage tracking and billing system
- **Multi-Tenant**: Organization and agent isolation

### Technical Stack

| Component      | Technology                       |
| -------------- | -------------------------------- |
| Language       | Rust (Edition 2024)              |
| Async Runtime  | Tokio                            |
| gRPC           | Tonic + Prost                    |
| REST API       | Axum                             |
| Database       | MongoDB 3.3.0                    |
| Pub/Sub        | Redis                            |
| Code Execution | Deno 0.233.0                     |
| HTTP Client    | Reqwest                          |
| Encryption     | AES-256-GCM, bcrypt, HMAC-SHA256 |
| TLS            | Rustls with Ring                 |

### Data Flow

1. **SDK Registration**: Node.js SDK connects via gRPC, authenticates, and registers available functions
2. **Query Processing**: Client sends query via gRPC or REST
3. **Phase 1 (Planning)**: LLM determines which tools/functions to call
4. **Function Execution**: Engine routes function calls to connected SDKs via Redis pub/sub
5. **Phase 2 (Execution)**: LLM generates final response using tool results
6. **Response Delivery**: Results streamed or returned to client

## gRPC Services

### Proto Definition

Located at `proto/daemo.proto`:

```protobuf
service DaemoGateway {
  // Bidirectional streaming for SDK connections
  rpc EstablishStream(stream ServiceMessage) returns (stream GatewayMessage);
}

service DaemoAgent {
  // Query Processing
  rpc ProcessQuery(QueryRequest) returns (QueryResponse);
  rpc ProcessQueryStreamed(QueryRequest) returns (stream QueryStreamResponse);

  // Thread Management
  rpc CreateThread(CreateThreadRequest) returns (CreateThreadResponse);
  rpc ListThreads(ListThreadsRequest) returns (ListThreadsResponse);
  rpc GetThread(GetThreadRequest) returns (GetThreadResponse);
  rpc DeleteThread(DeleteThreadRequest) returns (DeleteThreadResponse);
}
```

### Gateway Service (`DaemoGateway`)

Manages SDK connections via bidirectional streaming:

**Message Types**:

| Message                | Direction     | Purpose                       |
| ---------------------- | ------------- | ----------------------------- |
| `AuthenticateRequest`  | SDK → Engine  | API key authentication        |
| `AuthenticationResult` | Engine → SDK  | Auth result with agent ID     |
| `RegisterRequest`      | SDK → Engine  | Register function definitions |
| `FunctionRequest`      | Engine → SDK  | Request function execution    |
| `FunctionResponse`     | SDK → Engine  | Return execution result       |
| `Heartbeat`            | Bidirectional | Keep connection alive         |

**Connection Lifecycle**:

```
1. SDK connects via EstablishStream()
2. SDK sends AuthenticateRequest with API key
3. Engine validates and returns AuthenticationResult
4. SDK sends RegisterRequest with session JSON (functions)
5. Engine stores session in MongoDB
6. Engine sends FunctionRequest when tools are called
7. SDK executes and returns FunctionResponse
8. Periodic Heartbeat messages maintain connection
```

### Agent Service (`DaemoAgent`)

Processes AI queries and manages conversation threads:

**Query Processing**:

```protobuf
message QueryRequest {
  string query = 1;
  optional string thread_id = 2;
  optional string session_id = 3;
  optional LlmConfig llm_config = 4;
  optional StorageConfig storage_config = 5;
  optional string role = 6;
  optional string context_json = 7;
  optional bool analysis_mode = 8;
  optional bool direct_mode = 9;
  optional string direct_mode_system_prompt = 10;
}

message QueryResponse {
  bool success = 1;
  string response = 2;
  string error_message = 3;
  string thread_id = 4;
  repeated ToolCallInfo tool_interactions = 5;
  int64 execution_time_ms = 6;
}
```

**Streaming Events** (`QueryStreamResponse`):

| Event                    | Description                 |
| ------------------------ | --------------------------- |
| `thought`                | Agent reasoning/planning    |
| `tool_call`              | Function invocation details |
| `tool_result`            | Function execution result   |
| `partial_response_chunk` | Streaming LLM tokens        |
| `final_response`         | Complete result             |
| `error`                  | Error message               |

## Two-Phase AI Execution

Daemo Engine uses a sophisticated two-phase approach for query processing:

### Phase 1: Planning

**Purpose**: Determine which tools/functions to call

**Default Provider**: Fireworks (GLM 4.7)
**Max Tokens**: 8192
**Max Steps**: 50

The planning phase:

1. Receives user query with available tool definitions
2. LLM analyzes query and decides on tool calls
3. Generates structured tool call requests with parameters
4. Returns tool calls to be executed

### Phase 2: Execution

**Purpose**: Execute tools and generate final response

**Default Provider**: Anthropic (Claude)

The execution phase:

1. Executes tool calls via Deno runtime or SDK functions
2. Collects results from all tool executions
3. LLM generates final response using tool results
4. Post-processes response (executes embedded TypeScript blocks)

### Execution Flow

```
User Query
    │
    ▼
┌─────────────────────────────────────┐
│ Phase 1: Planning (Fireworks GLM)   │
│                                     │
│ Input: Query + Tool Definitions     │
│ Output: List of Tool Calls          │
└────────────────┬────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────┐
│ Tool Execution (Deno Runtime)       │
│                                     │
│ • SDK Functions (via gRPC/Redis)    │
│ • Hosted Edge Functions             │
│ • Built-in Tools (respond, search)  │
└────────────────┬────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────┐
│ Phase 2: Execution (Claude)         │
│                                     │
│ Input: Query + Tool Results         │
│ Output: Final Response              │
└────────────────┬────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────┐
│ Post-Processing                     │
│                                     │
│ Execute embedded TypeScript blocks  │
│ in markdown response                │
└────────────────┬────────────────────┘
                 │
                 ▼
            Final Response
```

## Function Execution & Tool Calling

### Function Types

#### 1. SDK Functions

Functions registered by connected Node.js or .NET SDKs:

- Registered via `RegisterRequest` with session JSON
- Invoked via `op_function_call` in Deno runtime
- Routed through Redis pub/sub for multi-instance support
- 60-second execution timeout

#### 2. Hosted Edge Functions

Managed functions stored in MongoDB:

- Created via REST API
- Executed directly in Deno runtime
- Include code (TypeScript) and schemas

#### 3. Built-in Tools

| Tool                  | Purpose                           |
| --------------------- | --------------------------------- |
| `ExecuteCodeTool`     | Run TypeScript code               |
| `RespondTool`         | Generate final response           |
| `SearchFunctionsTool` | Vector search available functions |
| `SearchMemoryTool`    | Vector search conversation memory |

### Function Execution Context

```rust
pub struct AgentTaskContext {
    pub agent_id: ObjectId,
    pub connections: ConnectionMap,        // Connected SDKs
    pub response_waiters: ResponseWaiterMap,
    pub redis_client: redis::Client,
    pub instance_id: Arc<String>,
    pub debug_context: Option<DebugContext>,
    pub hosted_functions: HashMap<String, EdgeFunction>,
    pub env_vars: HashMap<String, String>,
}
```

### Deno Runtime

The engine uses Deno for TypeScript/JavaScript execution with custom ops:

| Op                 | Purpose                         |
| ------------------ | ------------------------------- |
| `op_fetch`         | HTTP requests with headers/body |
| `op_function_call` | Invoke SDK functions            |

### Redis Pub/Sub for Function Routing

For multi-instance deployments:

```
Request:  daemo:requests:{instance_id}
Response: daemo:response:{request_id}
```

## Authentication & Security

### Authentication Methods

#### 1. REST API (JWT)

NextAuth-compatible JWT validation:

```
Authorization: Bearer <token>
```

Claims:

```rust
pub struct NextAuthClaims {
    pub user_id: String,
    pub email: Option<String>,
    pub iat: usize,
    pub exp: usize,
    pub jti: String,
}
```

#### 2. gRPC Services (API Key)

```
Metadata: x-api-key: <api_key>
```

### API Key Management

**Format**: `daemo_live_<48 random alphanumeric>`

**Storage**:

- `api_key_hash`: bcrypt hash (DEFAULT_COST = 10)
- `api_key_lookup`: HMAC-SHA256 for fast indexing
- `api_key_prefix`: Display-only prefix

**Lookup Process**:

1. Compute HMAC-SHA256(pepper, api_key)
2. Query `api_key_lookup` index
3. Verify bcrypt hash
4. Return agent if valid

### Encryption (AES-256-GCM)

Used for:

- Organization environment variables
- Custom MongoDB URIs
- Sensitive string data

```rust
// Requires MONGODB_ENCRYPTION_KEY (base64-encoded 32 bytes)
encrypt_string(plaintext: &str) -> Result<String>
decrypt_string(ciphertext: &str) -> Result<String>
```

### Security Measures

- bcrypt for API key hashing
- AES-256-GCM for data encryption (random nonce per encryption)
- HMAC-SHA256 for indexable lookups (with pepper)
- TLS support for gRPC in production
- JWT expiration validation

## Daemo Node SDK Integration

The Daemo Node SDK (`daemo-engine` npm package) enables you to build AI agent services that connect to the Daemo Engine Backend.

### Installation

```bash
npm install daemo-engine
```

### Core Components

#### 1. DaemoBuilder

Creates and configures your agent service:

```typescript
import { DaemoBuilder, SessionData } from "daemo-engine";

const builder = new DaemoBuilder()
  .withServiceName("my_service")
  .withSystemPrompt("You are a helpful assistant...");

// Register your service classes
builder.registerService(new MyFunctions());

// Build session data
const sessionData: SessionData = builder.build();
```

#### 2. DaemoHostedConnection

Establishes persistent gRPC connection to the engine:

```typescript
import { DaemoHostedConnection } from "daemo-engine";

const connection = new DaemoHostedConnection(
  {
    daemoGatewayUrl: "https://your-engine.com:50052",
    agentApiKey: process.env.DAEMO_AGENT_API_KEY,
  },
  sessionData,
);

await connection.start();
```

#### 3. DaemoClient

Makes queries to the engine (for client applications):

```typescript
import { DaemoClient } from "daemo-engine";

const client = new DaemoClient({
  daemoAgentUrl: "https://your-engine.com:50052",
  agentApiKey: process.env.DAEMO_AGENT_API_KEY,
});

// Process query
const result = await client.processQuery("What's the weather?", {
  threadId: "thread-123",
  sessionId: "my_service",
});

// Streaming query
const stream = client.processQueryStreamed(
  "Analyze this data...",
  {
    onData: (event) => console.log(event),
    onError: (error) => console.error(error),
    onEnd: () => console.log("Done"),
  },
  { threadId: "thread-123" },
);
```

#### 4. DaemoFunction Decorator

Marks methods as callable functions:

```typescript
import { DaemoFunction } from "daemo-engine";
import { z } from "zod";

class MyFunctions {
  @DaemoFunction({
    description: "Gets weather for a city",
    tags: ["weather"],
    category: "Weather",
```

```typescript
export async function startHostedConnection(
```

### Step 4: Create Express Server

Create `src/app.ts`:

```typescript
import express, { Request, Response } from "express";
import cors from "cors";
import { configDotenv } from "dotenv";
import { DaemoClient, LlmConfig } from "daemo-engine";
import {
  initializeDaemoService,
  startHostedConnection,
  getSessionData,
} from "./services/daemoService";

configDotenv();

async function startServer() {
  // Initialize Daemo
  console.log("Initializing Daemo Service...");
  const sessionData = initializeDaemoService();
  console.log(`Registered ${sessionData.Functions.length} functions`);

  // Start hosted connection
  await startHostedConnection(sessionData);

  // Create Express app
  const app = express();
  app.use(cors());
  app.use(express.json());

  // Create Daemo client for API calls
  const client = new DaemoClient({
    daemoAgentUrl: process.env.DAEMO_GATEWAY_URL || "localhost:50052",
    agentApiKey: process.env.DAEMO_AGENT_API_KEY,
  });

  // Health check
  app.get("/health", (_, res) => {
    res.json({ status: "ok" });
  });

  // Query endpoint
  app.post("/query", async (req: Request, res: Response) => {
    try {
      const { query, thread_id } = req.body;

      const result = await client.processQuery(query, {
        threadId: thread_id,
        sessionId: sessionData.ServiceName,
      });

      res.json({
        success: result.success,
        response: result.response,
        threadId: result.threadId,
        toolInteractions: result.toolInteractions,
      });
    } catch (error: any) {
      res.status(500).json({ error: error.message });
    }
  });

  // Streaming query endpoint
  app.post("/query-stream", (req: Request, res: Response) => {
    const { query, thread_id } = req.body;

    res.setHeader("Content-Type", "text/event-stream");
    res.setHeader("Cache-Control", "no-cache");
    res.setHeader("Connection", "keep-alive");
    res.flushHeaders();

    const stream = client.processQueryStreamed(
      query,
      {
        onData: (data) => {
          res.write(`data: ${JSON.stringify(data)}\n\n`);
        },
        onError: (error) => {
          res.write(
            `event: error\ndata: ${JSON.stringify({ message: error.message })}\n\n`,
          );
          res.end();
        },
        onEnd: () => {
          res.write(`event: end\ndata: {}\n\n`);
          res.end();
        },
      },
      {
        threadId: thread_id,
        sessionId: sessionData.ServiceName,
      },
    );

    res.on("close", () => {
      stream.cancel();
    });
  });

  const port = process.env.PORT || 5000;
  app.listen(port, () => {
    console.log(`Server running at http://localhost:${port}`);
  });
}

startServer().catch(console.error);
```

## API Reference

### gRPC Service: DaemoGateway

#### EstablishStream

Bidirectional streaming for SDK connections.

**Request Stream** (`ServiceMessage`):

- `auth`: Authentication request
- `register`: Function registration
- `function_response`: Function execution result
- `heartbeat`: Keep-alive

**Response Stream** (`GatewayMessage`):

- `auth_result`: Authentication result
- `function_request`: Function execution request
- `heartbeat`: Keep-alive

### gRPC Service: DaemoAgent

#### ProcessQuery

Unary RPC for query processing.

**Request**:

```protobuf
QueryRequest {
  string query
  optional string thread_id
  optional string session_id
  optional LlmConfig llm_config
  optional StorageConfig storage_config
  optional string role
  optional string context_json
  optional bool analysis_mode
  optional bool direct_mode
  optional string direct_mode_system_prompt
}
```

**Response**:

```protobuf
QueryResponse {
  bool success
  string response
  string error_message
  string thread_id
  repeated ToolCallInfo tool_interactions
  int64 execution_time_ms
}
```

#### ProcessQueryStreamed

Streaming RPC for real-time responses.

**Request**: Same as `ProcessQuery`

**Response Stream** (`QueryStreamResponse`):

- `thought`: Agent reasoning
- `tool_call`: Function invocation
- `tool_result`: Function result
- `partial_response_chunk`: Streaming tokens
- `final_response`: Complete result
- `error`: Error message

#### Thread Management

- `CreateThread`: Create new conversation thread
- `ListThreads`: List all threads for session
- `GetThread`: Get thread details and messages
- `DeleteThread`: Remove thread

### Common Issues

#### SDK Not Connecting

1. Check `DAEMO_AGENT_API_KEY` is set correctly
2. Verify gateway URL is reachable
3. Check TLS configuration (use `https://` for production)
4. Look for authentication errors in logs

1. Verify function is registered (check console logs)

3. Check function name doesn't conflict
4. Verify session is registered in MongoDB

#### Query Timeouts

1. Increase timeout in client options
2. Check LLM provider API keys
3. Verify Redis connection for function routing
4. Check function execution time

#### Memory/Thread Issues

1. Verify MongoDB connection
2. Check storage configuration
3. Ensure thread IDs are valid
4. Check for memory cleanup policies

## What is Simpson's Diversity Index?

Simpson's Diversity Index measures how evenly distributed different crime types are within a state. The index ranges from **0 to 1**:

- **Closer to 1**: High diversity - crimes are spread across many different types (no single crime dominates)
- **Closer to 0**: Low diversity - crimes are concentrated in just a few types

The formula is: **D = 1 - Σ(ni/N)²**

- Where ni = count of each offense type
- Where N = total offenses



### Filter by state:
```sql

```

### Count distinct incidents:
```sql
COUNT(DISTINCT CONCAT(ori, '-', incident_number)) as incident_count
```

### Calculate crime rate per 100k:
```sql
COUNT(*) * 100000.0 / MAX(CAST(ag.population AS INT64)) as rate_per_100k
```

## Example Queries

### Homicides by State
```sql
SELECT ag.state_abbr, COUNT(*) as homicides
FROM nibrs_data.offense_segment o
JOIN nibrs_data.agencies ag ON o.ori = ag.ori
WHERE o.ucr_offense_code = '09A' AND o.data_year = 2024
GROUP BY 1 ORDER BY 2 DESC
```

### Crime Rate by Agency
```sql
SELECT 
    ag.agency_name,
    ag.state_abbr,
    COUNT(*) as crimes,
    CAST(ag.population AS INT64) as population,
    ROUND(COUNT(*) * 100000.0 / CAST(ag.population AS INT64), 2) as rate_per_100k
FROM nibrs_data.offense_segment o
JOIN nibrs_data.agencies ag ON o.ori = ag.ori
WHERE o.data_year = 2024 AND CAST(ag.population AS INT64) > 100000
GROUP BY 1, 2, 4
ORDER BY 5 DESC
LIMIT 20
```

```sql
SELECT sex_of_victim, race_of_victim, COUNT(*) as count
FROM nibrs_data.victim_segment
WHERE type_of_victim = 'I' AND data_year = 2024
GROUP BY 1, 2 ORDER BY 3 DESC
```
